# Meta Muse向け移行仕様

更新日: 2026-11-08

M5Stack StopWatch C152の会話先をChatGPT dotsからMeta Museへ変更します。接続の土台には、Muse Gadget SDKに含まれるStopWatch実装を使用します。本体のマイクとスピーカー、Wi-Fiによる直接接続を維持する方針です。

既存のすみ画像と操作を維持し、返答の声をMuse音声とsanoTTS-jpから変更できる仕様で確定しました。初回はファームウェア変更とビルドまで実施し、追加依頼により2026-11-08にC152への書き込み、起動確認、SDKトークン設定、Wi-Fi接続、ペアリングを進めました。実機で判明したメモリー不足と辞書初期化時の再起動を修正し、sanoTTS-jp方式でMuseへの発話から本体での返答読み上げまで確認しました。Muse音声通話の開始時に発生するHTTP 404は未解決です。実装と手順は[`muse/README.md`](../muse/README.md)、確認結果と未検証項目は[`muse/VALIDATION.md`](../muse/VALIDATION.md)にまとめています。

## 既存仕様の基準

[共有チャット](https://chatgpt.com/s/cx_6aef94c426fc8191b0bc93c37cfd9c88)の後半で確定した仕様と、現在の[README](../README.md)を基準にします。初期案の「再押下・無音で録音停止」と「右ボタンで通話」は、その後変更されています。

| 項目 | 引き継ぐ仕様 |
| --- | --- |
| 入力 | 左ボタンを押して録音し、離して送信。通常の音声メッセージは入力遅延の補正として解放後120 msを含め、録音全体は最長15秒。赤い録音表示と入力レベルを表示 |
| 出力 | 本体スピーカーで返答を再生。返答本文は吹き出しに2行で表示し、音声に合わせて行送り。エラー文は見切れないよう、必要な高さまで吹き出しを広げる |
| 待機画面 | SUMIバッジ。会話中は既存のカラーアバターを表示 |
| 返信待ち | アバターの下端を固定し、上半身を左右に揺らす。返信待ちの時間経過だけではバッジに戻さない |
| 文言 | 「左ボタンを押して話しかけてね」「お話を聞いてるよ」「お返事を考えてるよ」 |
| 設定 | 右ボタンで開閉。上下スクロールの一覧から、大きなスライダーまたは時間選択画面へ遷移 |
| 調整項目 | 音量、アバターと明るいバッジの輝度、アバター・バッジ明・バッジ暗の表示時間。設定を本体に保存 |
| 戻る操作 | 画面下部の大きな「戻る」ボタン |
| 表示時間 | 初期値はアバター30秒、バッジ明60秒、バッジ暗60秒。その後消灯。設定候補は各15・30・45・60秒 |
| 電源ボタン | 点灯中の短押しで消灯。消灯中はいずれかのボタンでバッジ明へ復帰し、その押下を録音などへ流用しない |
| 状態表示 | バッテリー残量とWi-Fi状態。アバターで常時表示、バッジ明では上端付近のタップで表示 |
| Wi-Fi変更 | 設定から開始し、スマートフォンで変更。新しい接続が成功したときに保存 |
| 受信 | バッジ表示中・消灯中でも返信を受け取り、アバター表示と読み上げへ移行 |
| 履歴 | 今後の発話・返答を全期間参照できること。既存のdots履歴は保持 |

画像を引き継いでも、dots側の「すみ」の人格設定・記憶・会話履歴がMuseへ自動移行するわけではありません。Muse側の会話相手の設定は別に扱います。

## 公式SDKで確認できたこと

調査基準は公式リポジトリのコミット `463bd2a05380fea4211b0099ad0f70933c108b20` です。以降の実装では、この版を固定して差分を管理する方針です。

- StopWatch C152用のボード実装が存在します。ESP32-S3、16 MBフラッシュ、8 MB PSRAM、466×466の丸形AMOLED、タッチ、マイク、スピーカー、電源管理に対応しています。[ボード実装](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/components/muse/boards/board_m5stack_stopwatch.c)
- 使用する開発環境はESP-IDF 6.0.3です。現在のArduinoスケッチへURLを差し替える方式ではなく、公式SDKを土台に画面と操作を移植します。[導入手順](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/README.md)
- SDK tokenとMuseスマートフォンアプリでペアリングします。アプリのSettings > DevicesでDeveloper modeを有効にし、Add Deviceから登録する手順です。登録後の会話通信は本体のWi-Fiを使います。[SDK token](https://gadgets.muse.ai/settings/sdk-tokens)、[導入手順](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/README.md)
- 通常の音声メッセージはMuse側で文字起こしされ、返答はテキストです。標準実装は字幕を表示するための無音データを作っており、スピーカー対応ボードでも通常返答が自動で読み上げられるわけではありません。[返答処理](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/components/muse/muse_chat_session.cpp)
- `CONFIG_MUSE_REALTIME_VOICE` で実験的な音声通話を有効にできます。StopWatchでは左の黄色ボタンを押している間に発話し、離しても通話を維持してMuseの返答音声を受け取ります。Muse側が端末からの通話を受け付けることが条件です。[音声通話の説明](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/README.md)
- 通話の音声は端末側APIでは16 kHz mono、通信上では24 kHzに変換されます。ユーザーの押下、認識した発話、返答字幕、音声、終了を区別できます。StopWatchでエコー除去付きの常時同時通話が保証されているわけではありません。[通話API](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/components/muse/muse_voice_call.h)
- 日本語字幕用にかな・漢字を含むフォントがあります。既存の吹き出し・日本語メニューの大きさと読みやすさは移植後に確認します。[フォント](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/components/muse/fonts/README.md)

## 音声方式の選択

| 方式 | 通信と再生 | 主な追加作業 |
| --- | --- | --- |
| Muse音声通話 | 本体音声を公式SDKでMuseへ送り、返答音声を本体で再生 | 通話の開始・終了、右ボタンと設定の両立、押下外の録音防止、字幕、切断時処理 |
| 音声メッセージとsanoTTS-jp | 本体録音を公式SDKでMuseへ送り、返答テキストを本体で音声化 | ESP-IDFでのsanoTTS-jp統合、辞書・モデル領域、分割合成、メモリー配分、字幕同期 |

両方式を実装し、設定の「返答の声」から切り替えます。初期値はMuseの声です。会話中は切り替えず、終了後に選択します。通常の音声メッセージからMuseの返答音声が取得できるという前提にはしません。

音声通話の標準設定は無操作45秒、最長15分です。左ボタンを離す操作は発話終了であり、通話終了ではありません。現在の「1回の録音につき1件の返信」との違いを画面で分かるようにします。[通話設定](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/components/muse/Kconfig)

## 構成の変更

```text
StopWatch C152
  マイク・ボタン → Muse Gadget SDK → Wi-Fi → Muse
  スピーカー・字幕 ← 返答音声、または返答テキスト＋本体TTS
```

Museとの会話経路では、現在のCloudflareによるOpenAI文字起こし、MCP Events、Chrome拡張の入力中継を不要にする方針です。既存のWorkerと履歴データはそのまま保持します。全期間の履歴保管にWorkerを再利用するかは、Museの履歴取得を検証した後で決めます。

既存の `SumiAvatar/` を直接置き換える前に、Muse版を独立したビルド対象として用意します。SDKの接続・暗号化・ペアリング処理は再実装せず、公式実装を使用します。既存画面の移植対象は画像、表示状態、設定値、ボタン操作です。M5CanvasとLVGLの違いがあるため、描画コードをそのままコピーして動作する前提にはしません。

## 標準SDKとの操作差分

| 操作 | 公式StopWatch版 | 既存仕様を維持する場合 |
| --- | --- | --- |
| 左の黄色ボタン | 通常版はスピーカー切替、通話有効版は発話 | 録音・発話に固定 |
| 右の青色ボタン | 通常版は録音、通話有効版はミュート・終話 | 設定画面を開閉。終話は画面内に独立した操作を用意 |
| 設定 | 左スワイプ | 右ボタンで開閉し、既存のスクロールと戻る操作を維持 |
| 待機 | Muse標準アバターと画面スリープ | バッジ明・バッジ暗・消灯を追加 |
| Wi-Fi初期設定 | Museアプリとのペアリング | 公式ペアリングを使用。既存の設定用Wi-Fiによる変更機能は別途移植 |
| 電源短押し | 画面スリープ・復帰 | 既存仕様と同じ。復帰直後の誤録音を防止 |

上表の右列を移植対象とします。右ボタンを終話にする標準動作と、既存の設定操作を同時に割り当てないようにします。[公式操作説明](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/devices/README.md)

## 会話履歴

SDKには端末の認証で `GET /chat/history` を呼ぶ経路があります。ただし、この経路だけで全期間保存、過去ページの網羅取得、音声通話の全文保存まで保証されたとは扱いません。[履歴APIの説明](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/AGENTS.md#requests-to-muses-vm-from-your-code)

実接続では、次の項目を検証します。

1. 端末から送った発話・返答がMuseアプリに表示されるか。
2. 音声通話の認識文・返答字幕が履歴に残るか。
3. ページ分割、取得上限、保存期間、重複排除に使えるID。
4. アプリから同時に話しかけた場合に、端末への返答と区別できるか。

全期間参照をMuseだけで満たせない場合は、既存の認証付き履歴ページへ追加保存する構成を検討します。dotsの既存履歴はMuseの履歴と由来を区別して保持し、過去の会話をMuseへ自動送信しません。

## 実装と検証の順序

1. **公式版の接続確認**：ESP-IDF 6.0.3と固定版SDKでStopWatch用ビルドを用意し、SDK tokenをローカルで設定。Museアプリでペアリングし、日本語の短い1往復を確認します。
2. **音声方式の確認**：Muse音声を選ぶ場合は通話の受入れ・実音声・字幕・終話を確認。sanoTTS-jpを選ぶ場合は辞書配置を決め、ローカル合成を検証します。
3. **操作と画面の移植**：選択した見た目、ボタン、設定、バッジ、画面遷移、日本語字幕を移植します。
4. **履歴と回復処理**：履歴保存、再接続、消灯中受信、切断中の録音中止、古い返答の混入防止を検証します。
5. **遅延と電力の確認**：複数回の日本語会話で、ボタン解放、送信完了、最初の返答文字、最初の音声、実際の再生開始を別々に記録します。バッテリー駆動とUSB接続を分けて確認します。

現在の約29.1秒は「再生キュー投入まで」の単発計測です。Muse版との比較では同じ計測点も残し、発話長・返答長・接続状態をそろえます。移行による短縮秒数は実測して判断します。

## 実機書き込み前の確認

現在のsanoTTS-jp辞書は `0x610000` に配置されていますが、公式Muse版の16 MB構成では `0x420000` から4 MBが第2アプリ領域です。旧辞書のアドレスをそのまま使うと重なるため、流用しません。[Museの領域構成](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/partitions_muse.csv)

書き込み時は、接続中のC152を確認し、その時点の16 MBフラッシュを退避します。旧版の設定がMuse版のNVSに自動移行するとは扱いません。ペアリングとWi-Fiを設定し直す手順、元のファームウェアへ戻す手順を用意します。

## 実装済みの範囲

- 公式SDKの固定版を取得し、StopWatch用の独立したESP-IDFビルドを作成しました。
- 既存PNGをビルド時に変換し、バッジ、アバター、下端を固定した揺れ、瞬き、口の動き、日本語字幕を移植しました。
- 右ボタンの設定、左ボタンの録音、復帰だけの押下、段階的な消灯、設定保存を実装しました。
- Muse音声通話とsanoTTS-jpの切替、非同期のローカル合成、音声の世代管理、16 kHzへの変換を実装しました。
- Wi-Fi変更用の一時AP、スマートフォン用フォーム、成功後の保存、取消、5分の制限を実装しました。
- 辞書は`0x830000`へ配置し、アプリを8 MBの単一領域にしました。製品情報の位置は維持し、OTAを無効にしました。
- ビルドとサイズ確認に成功しました。アプリは約4.8 MBです。生成物は`muse/dist/`、配置とハッシュは`flash-plan.json`にあります。

## 実接続後の確認事項

Museアプリ・アカウントとSDK tokenを用意し、両方式の日本語会話、消灯中受信、通信復帰、Wi-Fi変更、設定保存、電力と遅延を確認します。トークンはチャットやGitへ記録せず、本体へ入力します。

全期間の履歴保管を保証する追加連携は未実装です。Muse側の履歴仕様を実接続で確認してから保存経路を決定します。既存のdots履歴は保持します。

本文の日本語表示はNoto Sans CJK JPの16 px・7,100字の部分フォント、設定は24 pxの部分フォントを使用します。どちらも16段階の濃淡で描画します。本文はJIS第1・第2水準の漢字を含みますが、旧フォントと同じ全CJK範囲ではありません。元のArduino版と同じ画像・配置方針を維持しますが、描画方式と文字の形は異なります。sanoTTS-jpの字幕送りは音声長の推定を含み、単語単位で一致する同期ではありません。


## 操作性改善（2026-11-08）

- ユーザー提供の既存サイドチャットとメインチャットを設定から選び、選択を保存します。新規の会話先は作成しません。送信、購読、受信イベント、受付応答の会話IDを照合します。
- sanoTTS-jpの速度を0.6〜1.2倍に調整できます。初期値は従来比0.8倍です。
- マイク感度と5秒間のローカル録音・再生テストを追加しました。録音テストはMuseへ送信しません。
- 入力遅延による末尾の切れを抑えるため、通常の音声メッセージではボタン解放後120 msを収録します。15秒上限と押下前の音声を送らない方針は維持します。
- Muse音声の404時は次回の発話を本体TTSで扱います。再選択でMuse音声を再試行できます。Muse側の404自体は未解決です。
- 設定文字を24 pxへ拡大し、一覧項目・スライダー・時間選択を再配置しました。

具体的な操作と提供状況は[README](../muse/README.md)、実機確認の範囲は[検証記録](../muse/VALIDATION.md)を参照してください。
