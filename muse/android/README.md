# すみ StopWatch Androidコンパニオン

C152の黄ボタンで録音し、スマホで文字起こし、Museとのテキスト会話、音声合成を行い、C152のスピーカーへ返します。既定はOpenAI `gpt-transcribe` とスマホ上のIrodori-TTS MF07です。接続先と `mcu-wearable` 設定は録音ごとに本体から受け取ります。対応するC152ファームウェアとAndroid 13以降が必要です。

## 初回設定

1. C152をBLEモードにするか、Wi-Fiモードで「スマホから設定」→「スマホ接続を開始」を選びます。「すみ StopWatch」の「StopWatchを探す」から本体を選択し、初回は本体の6桁コードをAndroidに入力します。
2. 「スマホの会話設定」でOpenAI APIキーと、BLE用に用意したMuse端末のアクセストークンを入力します。VM IDを空欄にするとアカウントの既定VMを選びます。MuseのSDKトークンは端末登録に使う別のトークンです。この版のアプリはMuse端末の新規登録・アクセストークンの自動更新を行いません。
3. Irodori Small-MF F16のGGUFを取り込み、元の `sumi-reference-v1.sumiref` または同じ12クリップから生成したMF用 `reference.voice.gguf` を取り込みます。アプリがモデルのSHA-256とMF07参照の条件を検査します。
4. 接続済みになったら黄ボタンを押したまま話します。登録したStopWatchへの自動接続は、「接続」画面で切り替えられます。オンの間は画面を閉じても接続を維持し、圏外から戻ると再接続します。通知を許可すると接続状態をスマホの通知欄でも確認できます。

C152の保存済み認証情報は読み出しません。OpenAIとMuseの認証情報は、このアプリのAndroid Keystoreで保護します。OpenAI ASRを選んだ場合はスマホからOpenAIに録音を送ります。

Android端末内の音声認識も選べます。端末に端末内認識サービスと日本語モデルがあり、C152からの録音入力をサポートしていることが条件です。Android側が録音入力を受け付けたと確認できない場合は結果を破棄します。マイク権限はAndroidのSpeechRecognizer APIが要求します。接続だけを試すときは「会話」画面の「テスト · 録音をそのまま再生」をオンにします。

## 設定と音声エンジン

「接続」画面で接続モード、会話先、mcu-wearable、音量、マイク感度、Wi-Fi時のASR、本体TTS速度、明るさ、表示時間、充電速度、Wi-Fi設定用ネットワークの開始・終了を操作できます。Wi-Fiネットワークへの参加情報は、本体で表示する設定用ページで入力します。Wi-Fiモードでの設定接続は5分間有効です。会話中や本体の設定処理中は変更を拒否します。

「会話」画面で音声エンジンの選択、OpenAIとMuseの認証、Irodoriのモデルと参照の取り込みを行います。「ログ」画面には、BLE転送、文字起こし、Museの送信・返信と容量表示の除去、Irodoriの入力と生成時間を表示します。最大300件をアプリのメモリに保持します。ログの絞り込み、コピー、消去、会話本文の記録停止は「ログ」画面で操作できます。

音声処理は `SpeechBackend.Asr`、`SpeechBackend.Chat`、`SpeechBackend.Tts` で分けています。ASRはサンプルレート付きモノラルPCMを受けてテキストを返し、TTSはテキストを受けてサンプルレート付きモノラルPCMを返します。各実装は完了・失敗の通知とキャンセルを提供します。選択肢への追加はMainActivityのプロバイダー登録で行い、ZonosやQwen系、別API、Haas-jaなどを接続する場合もBLE部分は共用できます。今回実装した選択肢はOpenAI ASR、Android端末内ASR、Irodori-TTSです。

## ビルド

Android SDK Platform 36、Build Tools 36.0.0、JDK 17以上、Python 3.11以上を用意します。Irodoriを含むAPKには、v0.45.0の公式配布APKをローカルファイルとして指定します。ビルド時にAPKの固定SHA-256を照合し、arm64ネイティブ実行ライブラリだけを取り込みます。重みと参照は端末へ別に取り込みます。

```sh
SUMI_IRODORI_APK=/path/to/irodori-offline-v0.45.0-debug.apk bash muse/android/build.sh
```

署名用キーストアを `SUMI_ANDROID_KEYSTORE` で指定した場合は署名済みAPKも生成します。MacでAndroid StudioのJDKを使う場合は `JAVA_HOME` に `/Applications/Android Studio.app/Contents/jbr/Contents/Home` を設定します。USBポートが1つの場合はAPKの導入後にXiaomiを外し、C152へ差し替えます。

## 音声転送 v1

既存のHome LinkのBLEサーバーにサービス `4d757365-0011-4000-8000-6a6f6c6c7900` を追加します。スマホから本体への書き込みは `0012`、本体からスマホへの通知と再生バッファ状態の読み取りは `0013` です。暗号化、認証済みのボンディング、通知購読後の `HELLO` を要求します。

すべてのメッセージは9バイトのヘッダー（種別1バイト、録音ごとのID 4バイト、位置または長さ4バイト）で始まります。整数はリトルエンディアンです。音声は16kHz、モノラル、符号付き16bitのPCMです。

| 方向 | 種別 | 位置・ペイロード |
| --- | --- | --- |
| スマホ→本体 | 1 `HELLO` | ID 0、位置 1（バージョン） |
| 本体→スマホ | 2 `NOTE_BEGIN` | 録音全体のバイト数。会話先と `mcu-wearable` の各1バイトが続く |
| 本体→スマホ | 3 `NOTE_PCM` | 録音中のバイト位置。続けてPCM |
| 本体→スマホ | 4 `NOTE_END` | 録音全体のバイト数 |
| スマホ→本体 | 5 `NOTE_ACK` | 連続受信した録音のバイト数 |
| スマホ→本体 | 6 `REPLY_BEGIN` | 返答音声全体のバイト数 |
| スマホ→本体 | 7 `REPLY_PCM` | 返答音声中のバイト位置。続けてPCM |
| スマホ→本体 | 8 `REPLY_END` | 返答音声全体のバイト数 |
| 本体→スマホ | 9 `CANCEL` | 位置0 |
| スマホ→本体 | 10 `ERROR` | 位置0 |
| 本体→スマホ | 11 `REPLY_STATUS` | 連続受信したバイト数。続けてバッファ空き容量4バイト |
| スマホ→本体 | 12 `CAPTION` | 位置0。最大235バイトのUTF-8本文プレビュー |

録音は最長15秒です。録音を受け取るスマホはACKを返し、再生音を送るときは本体の受信済み位置とバッファ残量を確認して送ります。再生は400msを先に確保するか、短い音声を最後まで受信した時点で始めます。再接続後に前の会話の音声は破棄されます。帯域や再生開始時刻は端末どうしの実測値を使って評価します。

設定は同サービスの特性 `0014` で読み書きします。設定値は本体で保存し、アプリは連番付きの結果を読み返します。音声用の通知購読とは独立しており、認証済みBLE接続が必要です。
