# すみ StopWatch / Meta Muse版

M5Stack StopWatch C152の既存のすみ画像と押して話す操作を、Meta Muse Gadget SDKへ移植した独立ビルドです。既存のArduino版 `SumiAvatar/`、Cloudflare Worker、dotsの履歴は保持します。

このディレクトリのビルド手順は本体へ書き込みません。Museとのペアリング、実音声、通信復帰、消費電力は実機での検証が必要です。

2026-11-08にC152へ書き込み、画面・音声部品の初期化、マイク入力、SDKトークンの保存、Wi-Fi接続、Museのペアリングと会話用接続を確認しました。実機で判明したメモリー不足と辞書初期化時の再起動を修正した後、sanoTTS-jp方式でMuseへの音声送信から本体での返答読み上げまで、ユーザーが実際に聞こえることを確認しました。連続使用時の安定性や電池駆動時の測定は未実施です。

[検証結果と未確認事項](VALIDATION.md)に、成功したテストとSDK全体テストの未対応項目を記録しています。

## 操作

- 左の黄色ボタンを押して録音し、離して送信します。最長15秒で録音を止め、そのまま押し続けても録音を延長しません。送信はボタンを離してからです。
- 右の青色ボタンで設定を開閉します。項目を上下にスクロールし、タップして調整します。画面下部の「戻る」で前の画面へ戻ります。
- 設定一覧の一番下にある「システム情報」で、実行中のファームウェアのバージョンを確認できます。
- 電源の短押しで消灯します。消灯中のボタン操作はバッジ表示へ戻すために使い、同じ押下で録音や設定変更を開始しません。画面タッチでは消灯から復帰しません。
- アバター30秒、明るいバッジ60秒、暗いバッジ60秒の順に表示して消灯します。各時間は15・30・45・60秒から選べます。返信待ちと再生中はアバターを維持します。
- 音量、マイク感度、読み上げ速度、会話先、アバターの明るさ、バッジの明るさ、表示時間、返答の声を保存します。電池残量とWi-Fi状態は明るい・暗い両方のバッジで常時表示します。
- バッジのどこかをタップすると画像を約70%に縮小して下へ寄せ、上に24時間表記の時計（HH:mm）を表示します。再タップで通常バッジへ戻ります。暗いバッジのタップも同じ切替を行い、明るさと表示時間を戻します。
- 時計は日本時間（JST）です。Wi-Fi接続後にNTPで自動同期し、同期後は接続が切れても動作中の時計を維持します。起動後の初回同期前は「--:--」と表示します。内蔵RTCへの保存・読み出しは今回の対象外です。

## 接続モードの試験版

この作業中のビルドでは「接続モード」からWi-FiまたはBLEを選び、電源を入れ直しても選択が残ります。会話中、Wi-Fi設定中、未送信の録音がある間は切り替えられません。

- Wi-FiではC152がMuseに直接接続し、返答を本体のsanoTTS-jpで読み上げます。会話先、音声認識、読み上げ速度の設定値を引き継ぎます。
- BLEでは登録済みのC152が本体Wi-Fiから切断し、スマホ用のサービスを有効にします。C152の黄ボタンで録音し、アプリが受け取った音声を本体で再生できます。バッジは電池とBLE接続状態を表示します。

Androidコンパニオンの会話経路と本体設定の読み書きを実装しました。導入と確認には[Androidコンパニオンの手順](android/README.md)を参照してください。会話版の実機検証状況は[検証記録](VALIDATION.md)にまとめています。以下の「Museの声」とリアルタイム音声通話の記述は、試験版導入前の仕様です。

## 会話先と音声の調整

設定の「会話先」で「M5Stack会話用」または「メインチャット」を選びます。前回の選択を保存します。この更新で会話先が未設定の場合は、ユーザーが共有した既存の[M5Stack会話用サイドチャット](https://muse.ai/thread/3622d9af-4010-4247-ac57-cd702e8bc9d3)を選択します。会話中や未送信の音声がある間は変更できません。

SDKには既存チャットの一覧取得APIがないため、一覧は登録済みの2件です。アプリ内の全サイドチャットを自動取得する機能ではありません。追加には共有URLのUUIDを登録する必要があります。選択したサイドチャットの購読に成功してから送信し、受信イベントと受付応答の会話IDも照合します。接続に失敗してもメインチャットへ自動転送しません。Muse音声通話にも同じチャットを指定し、開始応答の会話先を照合します。

- 「読み上げ速度」: sanoTTS-jpを0.6〜1.2倍、0.1刻みで調整します。従来の速度が1.0倍で、初期値は0.8倍です。音程を変える再生レート変更ではなく、合成時の発音の長さを調整します。次の返答から適用します。
- 「マイク感度」: 0〜36 dBを3 dB刻みで調整します。既存の設定値を維持し、勝手に感度を上げません。
- 「録音を聞き返す」: 開始すると5秒間録音し、本体で再生します。音声はMuseへ送信しません。録音中と再生中の表示を確認して話してください。
- 通常の発話では、ボタン解放後に120 msだけ録音を続け、入力部品の遅れによる末尾切れを補正します。押下前の音声は追加せず、録音全体の15秒上限は維持します。
- 設定の固定文字はNoto Sans CJK JPの24 px、吹き出し本文は同フォントの16 pxで、いずれも16段階の濃淡で輪郭を描画します。本文はJIS第1・第2水準の漢字、かな、記号など7,100字を収録します。旧フォントの中国語・韓国語を含む全CJK範囲とは収録範囲が異なります。一覧のボタンは高さ52→64 pxに拡大しました。音声メニューなどは上下スクロールで選べます。

「音声認識」でMuseまたはOpenAIを選べます。OpenAIでは本体からHTTPSで `gpt-transcribe` に16 kHz・16 bit・モノラルWAVを送り、日本語の言語ヒントとM5Stack／Muse／StopWatchの用語ヒントを付けます。Macや中継サーバーの常時起動は不要です。認識結果は選択中のMuseチャットへ通常のテキスト形式で送信し、返答は本体のsanoTTS-jpで読み上げます。Museの音声通話APIは使いません。言語・用語ヒントは[OpenAI公式の音声認識仕様](https://developers.openai.com/api/docs/guides/speech-to-text)に従いますが、改善幅は実際の発話で比較が必要です。

OpenAIを使う前に、USB接続したMacで `muse/.cache/idf-tools/python_env/idf6.0_py3.13_env/bin/python muse/set_openai_key.py --dialog` を実行します。ログ取得やscreenを終了してから操作してください。入力を隠す画面へAPIキーを入力すると、本体のNVSに保存してOpenAI認識へ切り替えます。キーをチャット・コマンド引数・Macのファイルへ保存しません。初回設定後はUSB不要です。APIの利用料が発生します。失敗時は理由を表示し、録音の自動再送やMuse ASRへの自動切替は行いません。設定でMuseへ戻せます。

「送信設定」で `mcu-wearable` をON／OFFに切り替え、選択を保存できます。初期値はONです。保存済みのON／OFFは維持します。ONではMuse宛てのチャット要求に `device: mcu-wearable` を付け、OFFではこの項目を省略します。OpenAIの認識結果を送る経路と、Museへ録音を送る経路の両方に適用します。会話中・未送信音声がある間は変更できません。各会話の開始時点で設定を固定するため、送信途中で切り替わりません。Museのリアルタイム音声通話に必要な端末IDは変更しません。

以前のOpenAI認識＋端末指定なしの経路で、同じサイドチャットに音声添付が生成されることを実機で確認しました。ASRと送信形式も同時に変更したため、device指定だけが差の原因かは未確定です。VMで生成された添付音声を本体へ取り込む機能や、Museのリアルタイム音声APIの404自体を修正する機能ではありません。

## バッテリー残量表示

残量は電圧から推定します。5サンプルの中央値で一時的な上下を除き、約45秒の時定数で平滑化します。2ポイントのヒステリシスを設け、通常は20秒に最大1ポイントだけ表示を更新します。USB切替後は20秒間、通常の表示更新を止めます。電池駆動中の残量増加は、電圧回復が2分以上続いた場合に限り、最大1分に1ポイントとします。

実際の低電圧を隠さないため、5サンプルの中央値が3,400 mV以下で10秒続いた場合は低残量へ追従します。I2C読み取り失敗や範囲外の値を0%として扱いません。ログ用の電圧は加工せず保持します。この変更は表示の安定化であり、実容量の校正や実際の消費電流削減を保証するものではありません。

## 返答の声

設定の「返答の声」から次の2方式を切り替えます。初期値はMuseの声です。会話中の切替は受け付けません。

2026-11-08の実機確認では、Museの音声通話開始APIがHTTP 404を返しました。Wi-Fi・登録・会話用接続は成功していますが、Museの声での通話は現在開始できていません。[公式リポジトリの同様の報告](https://github.com/facebookincubator/muse-gadget-sdk/issues/310)も未解決で、提供状況や利用条件の詳細は未確定です。404を受けた場合は「次の発話は本体の声」と表示し、次回からsanoTTS-jp方式へ一時的に切り替えます。失敗した発話を別の会話先へ自動再送することはありません。「Museの声を試す」を選び直すと再試行できます。この代替状態は電源を切ると解除されます。

| 選択 | 動作 |
| --- | --- |
| Museの声 | 公式SDKの実験的な音声通話を使用します。左ボタンを離すと発話を送信し、通話は継続します。設定の「通話を終了」で終了できます。Muse側で端末の通話が利用可能である必要があります。 |
| sanoTTS-jp（本体） | 音声メッセージをMuseへ送り、返答テキストを本体で日本語音声へ変換します。現在の月読モデルと辞書を使用します。 |

ローカル音声は別の処理で合成し、有限長のキューを通じて再生します。先頭約1.6秒を合成してから再生し、短い返答では合成完了後に再生します。合成音の最大振幅・上限到達数、合成時間とキュー待機時間、再生中に音声が不足して無音を補った時間をログへ残します。再生中は次の音声データを最大20 ms待ってから不足を判定し、短い処理の遅れで無音が入るのを抑えます。22,050 HzからSDKの16,000 Hzへ変換する前に、63タップ・7 kHzのローパスフィルターで折り返しノイズを抑えます。ユーザー比較ではこの更新で音質は改善しましたが、同じモデルをMac上で合成した変換前の音にも金属的な質感が残っています。長文はUTF-8の文字境界と句読点を使って分割します。キャンセル後の音声は会話の世代番号で破棄します。送信した録音の控えはMuseが受信を確認した時点で解放し、合成用のメモリーを確保します。辞書がない、壊れている、メモリーが不足する、または読み上げできない文章の場合はエラーを表示します。

[Issue #6](https://github.com/facebookincubator/muse-gadget-sdk/issues/6)の公式対応は[PR #12](https://github.com/facebookincubator/muse-gadget-sdk/pull/12)で行われたテキスト返答への切替と旧TTS取得の削除です。この対応は固定版SDKに含まれています。現在発生している `/voice/realtime` の404は別の問題であり、本体側の代替音声を追加してもMuse固有の声が復旧したとは扱いません。

字幕はSDKのページ送りを利用します。sanoTTS-jpでは合成中の音声長を推定するため、厳密な単語単位の同期ではありません。Muse音声ではサーバーから届く字幕に従います。

## 初回ビルド

必要な環境はPython 3.10〜3.13、ESP-IDF **6.0.3**、CMake、Ninjaです。この環境ではPython 3.13.13を使用しました。初回はSDK、コンパイラ、辞書などのダウンロードが発生します。`.cache/`は数GBになります。

1. Pythonの環境を用意します。下の`python3.13`は使用可能な対応版に読み替えられます。

   ```sh
   python3.13 -m venv muse/.cache/host-venv
   muse/.cache/host-venv/bin/python -m pip install 'pillow==12.2.0' 'cmake==4.3.1' 'ninja==1.13.0'
   ```

2. [ESP-IDF 6.0.3の公式リリース](https://github.com/espressif/esp-idf/releases/tag/v6.0.3)の`esp-idf-v6.0.3.zip`を`.cache/`へ展開します。GitHubの自動生成Source codeではなく、サブモジュールを含むリリース用ZIPを使います。

   ```sh
   export PATH="$PWD/muse/.cache/host-venv/bin:$PATH"
   export IDF_TOOLS_PATH="$PWD/muse/.cache/idf-tools"
   muse/.cache/esp-idf-v6.0.3/install.sh esp32s3
   ```

3. リポジトリのルートでビルドします。

   ```sh
   bash muse/build.sh
   ```

既存のESP-IDFを使う場合は`IDF_PATH`と`IDF_TOOLS_PATH`を指定できます。`SUMI_PYTHON`で画像変換用のPythonを指定できます。SDKの変更は`overlay/`・`main/`・`sdk.patch`で管理し、`prepare.py`が固定版ソースへ適用します。SDKとsanoTTS-jpの取得物はSHA-256を照合します。

ビルドにはSDK tokenを埋め込みません。実機では[SDK tokenの発行画面](https://gadgets.muse.ai/settings/sdk-tokens)で発行し、公式手順のシリアル入力`>sdk_token=...`で本体へ保存します。トークンをソース、Git、共有ログへ記載しないでください。

macOSでは次のコマンドで、値を表示しない入力ダイアログから設定できます。`screen`や他のシリアルモニターは先に終了してください。接続先がC152であることを確認してから送信し、本体の保存完了応答を確認します。

```sh
muse/.cache/idf-tools/python_env/idf6.0_py3.13_env/bin/python muse/set_sdk_token.py --dialog
```

`screen`で入力する場合、本体は入力文字を表示しません。また、コマンドの確定にはLFが必要なので、末尾で**Ctrl+J**を押します。終了は**Ctrl+A → K → Y**です。タブを閉じるだけでは接続が残る場合があるため、`screen -ls`で確認し、対象のセッションだけを`screen -S セッション名 -X quit`で終了してください。

## 初回書き込みとペアリング

生成物は`dist/`、アドレスとSHA-256は`dist/flash-plan.json`にまとめます。全領域を一つに結合したイメージは生成しません。

既にこのMuse版を使用しており領域構成が一致するC152への更新では、アプリ（`0x20000`）だけを更新し、NVS・製品情報・辞書を保持します。以下のNVS初期化はArduino版からの初回移行に限ります。

現在のArduino版とは領域構成が変わります。書き込みを行う際は、接続対象がC152であることを確認し、**現在の16 MBフラッシュ全体を読み出して退避してから**移行してください。旧辞書の`0x610000`は使用しません。旧設定の自動移行は行わないため、新しいNVS領域の初期化と再設定が必要です。

| 内容 | 開始アドレス | 上限 |
| --- | --- | --- |
| ブートローダー | `0x000000` | 64 KB |
| 領域テーブル | `0x010000` | 4 KB |
| NVS（設定、ペアリング） | `0x011000` | 48 KB |
| OTA管理領域 | `0x01D000` | 8 KB |
| アプリ | `0x020000` | 8 MB |
| 製品情報、バックアップ | `0x820000`、`0x821000` | 各4 KB、保持 |
| sanoTTS-jp辞書 | `0x830000` | 6,815,744 bytes |

アプリ領域を1つにして辞書を収めるため、OTA更新は無効です。Secure BootやeFuseの有効化は行いません。書き込みにはSDKが生成する各イメージと専用辞書を使用します。`prod_data`と`prod_bak`を消す全消去や、空白領域を埋めた全体イメージは使わないでください。元に戻す場合は移行前に退避したフラッシュを復元します。

### BLEで更新できる構成

OTA用ビルドは4 MiBのアプリ領域を2つ使います。画像は `sumi-assets.bin` として共有領域 `0xEB0000` に置きます。辞書と製品情報は上の表と同じ位置です。

```sh
SUMI_OTA=1 SUMI_OTA_VERSION=0.1.0 \
  SUMI_BUILD_DIR="$PWD/muse/.cache/c152-ota-build" \
  SUMI_DIST_DIR="$PWD/muse/.cache/c152-ota-dist" bash muse/build.sh
```

初回のOTA用ビルドで署名鍵を `muse/.cache/ota-signing/c152.pem` に作成します。以降も同じ鍵で署名します。別の保管場所を使うときは `SUMI_OTA_SIGNING_KEY` に既存の秘密鍵を指定します。署名鍵は配布物に含めません。

すみ StopWatch v0.3.18とC152 v0.1.5から、署名済みの `sumi-muse.bin` をアプリで圧縮してBLE転送します。C152は展開したイメージを空きスロットに書き込み、署名検証と再起動後の確認を行います。v0.1.4以前からv0.1.5へ更新するときは従来の転送を使います。ATT MTUを517にした状態でビルドするには、新しい `SUMI_BUILD_DIR` を指定します。

Android v0.3.20とC152 v0.1.7以降では、圧縮OTAのデータを最大24パケットずつ送信し、各区間の終わりにC152の受信位置を照合します。欠落があれば未受信位置から再送し、繰り返す場合はパケットごとの応答を使います。C152 v0.1.6からv0.1.7を入れる回は、圧縮とパケットごとの応答で転送します。

現行のすみファームから初めて移行するときは、フラッシュ全体をバックアップし、`verify-flash` で照合した後、OTA用のブートローダー、パーティションテーブル、初期OTA管理領域、アプリ、共有画像を書き込みます。設定と登録を引き継ぐため、NVS、製品情報、辞書は保持します。配布先の `flash-plan.json` で各アドレスとSHA-256を確認できます。書き込み後はアプリが `ota_0` から起動し、BLEで接続できることを確認します。

次回からはBLEモードでAndroidの「接続」→「C152ファームウェアを更新」を開き、その機器用に署名した `sumi-muse.bin` を選びます。C152は空きスロットで署名を検証してから再起動します。新ファームが画面を初期化し、BLEで再接続できたら起動を確定します。確定できない場合は旧スロットへ戻ります。Androidは起動スロットとビルドIDを読み返して結果を表示します。

MuseアプリのSettings → DevicesでDeveloper modeを有効にし、Add Deviceから登録します。ペアリングの確認要求は左ボタンで確定します。登録が済むまでは公式SDKのセットアップ画面を表示します。登録後は本体のWi-FiでMuseへ直接接続します。詳細は[公式導入手順](https://github.com/facebookincubator/muse-gadget-sdk/blob/463bd2a05380fea4211b0099ad0f70933c108b20/esp32/README.md)を参照してください。

## USB接続中の待機音

C152のスピーカーアンプは再生時だけ有効にし、終端に120 msの無音を流してから停止します。音量0%でもアンプを停止します。マイクと共有する音声回路の電源は維持するため、次の録音で電源投入待ちは発生しません。USB接続中の高周波音はアンプ停止後も変わらず、ユーザーから別電源でも発生し、満充電では止まると報告を受けています。充電中の回路動作との関連は考えられますが、発音源は未特定です。

設定の「充電速度」で標準185 mA／高速425 mAを選択できます。初期値は既存の425 mAです。M5PM1 GPIO3の設定を読み戻して確認できた場合だけ選択を保存し、再起動後も適用します。標準は入力・プルなし、高速はプッシュプル出力LOWという[メーカー指定の方式](https://docs.m5stack.com/en/arduino/stopwatch/m5pm1_m5ioe1)を使います。表示する電流はモードの公称値で、実測電流ではありません。実機比較では185 mAへ切り替えても充電音は変わらないとの報告で、発音源は引き続き未特定です。

## Wi-Fi変更

Wi-Fiモードで、設定の「Wi-Fiを変更」→「Wi-Fiを追加・更新」を選びます。本体に表示される`SUMI-SETUP-xxxx`と一時パスワードでスマートフォンを接続し、`http://192.168.4.1`を開きます。2.4 GHzのネットワーク名とパスワードを入力してください。

接続できた設定を最大8件保存します。同じSSIDを入力すると、接続確認後にパスワードを更新します。失敗時は再入力できます。5分経過または「戻る」で設定用Wi-Fiを閉じ、保存済みのネットワークへ戻ります。

保存済みの一覧でSSIDを選び、「このWi-Fiに接続」でパスワードを再入力せずに切り替えます。選んだネットワークに接続できない場合は、保存済みの別のネットワークへ再接続を試みます。「保存済みWi-Fiを削除」→「削除する」で選んだ1件を削除できます。会話と未送信の録音を終えてから操作してください。

## 履歴と検証範囲

既存のdots履歴とWorkerは変更しません。Muse側へ人格・記憶・過去の会話を自動送信する処理は含めません。今後のMuse会話の履歴については、アプリへの反映、音声通話の全文、`/chat/history`の保存期間と取得上限を実接続で確認する必要があります。全期間保管を保証する追加の履歴連携は未実装です。[移行仕様](../docs/meta-muse-migration.md)に確認項目をまとめています。

実機で確認する項目は、両音声方式での日本語1往復、15秒上限とボタン解放、消灯中受信、音声切替、Wi-Fiの成功・失敗・取消、再起動後の設定保持、長文と読み上げ失敗、電池駆動時のメモリー・遅延・消費電力です。コンパイルと画面のホスト検証だけでは、これらの成功を保証しません。

## ローカル検証

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined \
  -I muse/overlay muse/tests/core_test.c -lm -o muse/.cache/core_test
muse/.cache/core_test
muse/.cache/host-venv/bin/python -m unittest discover -s muse/tests -v
export PATH="$PWD/muse/.cache/host-venv/bin:$PATH"
cmake -S muse/tests -B muse/.cache/ui-build -G Ninja
cmake --build muse/.cache/ui-build
(cd muse/.cache/ui-build && ./render_ui)
```

画面テストは実際のLVGLと移植したUIを使い、画面遷移を検証してPPM画像を出力します。ハードウェア、ネットワーク、NVSはテスト用の置換実装です。SDKの既存テストには標準ボタン配置を前提とするものがあるため、変更後の操作は本プロジェクトのテストで検証します。

読み上げ用の文から絵文字・装飾記号を除きます。チャットと画面には元の文を表示します。sanoTTS-jpの辞書が白いハート（🤍）を含む文で解析に失敗するための対応で、絵文字だけの返答は無音で完了します。

### 合成速度と外部5Vの診断

合成処理はcore 0へ固定し、同じアバターの見た目を繰り返し描画する処理を省きます。画面・音声入出力はcore 1で動作します。USBコンソールの `>sumi.power` で外部5V出力の有効化ビット、充電許可、設定電流を読み戻せます。外部5V昇圧は起動時に停止し、停止設定を確認します。設定ビットは端子電圧の測定値ではありません。

待機中の `>sumi.tts_bench` は固定文を本体内だけで合成し、CPU周波数・実行core・処理時間を記録します。マイク・スピーカー・外部APIは使用しません。診断中に通常の読み上げが始まれば、その会話が優先されます。

### USB接続時の高周波音の切り分け結果

2026-11-09時点で、USB接続中の高周波音は解消していません。ユーザーの実機確認は次のとおりです。

| 比較条件 | 結果 |
| --- | --- |
| Mac以外のUSB電源 | 同様に発生 |
| 音量0%、画面消灯 | 変わらない |
| アンプ停止、音声回路停止、表示回路停止 | 変わらない |
| 185mAと425mAの切替、充電許可の20秒停止 | 変わらない |
| 外部5V昇圧停止 | 現行版で設定を読み戻し、OFFを確認。音は残る |
| メーカー標準ファームV0.5 | 同じように鳴る |
| USBを抜く、本体を完全に電源OFF | 止まる |
| 満充電 | 鳴らないとの報告あり |

充電許可・外部5V停止の確認は設定レジスターの読み戻しであり、実電流・端子電圧の測定ではありません。標準ファーム比較時の電池残量も未確認です。標準版でも再現するため、Muse専用のソフトウェアだけを原因とする根拠は弱くなりました。発音部品や個体不良の有無は特定しておらず、ソフトウェア修正済みとは扱いません。

次の対応は販売店・メーカーによる点検、同型機との比較、必要に応じた交換相談です。[M5Stackの公式窓口](https://shop.m5stack.com/pages/contact-us)では技術問い合わせ先としてsupport@m5stack.comが案内されています。上記の比較結果を提示できます。FlashバックアップにはAPIキー等が含まれるため、問い合わせ資料には含めません。

### 英数字・製品名の読み上げ

合成前にOpen JTalk標準の文字正規化を行い、半角英数字を辞書で処理できる形式にそろえます。M5Stackは「エムファイブスタック」、Museは「ミューズ」、StopWatchは「ストップウォッチ」という読みを補います。英字だけの未知語は文字ごとの読みになる場合があり、任意の英文が自然な発音になることを保証するものではありません。チャット本文と字幕は変更せず、読み上げ用のコピーだけを処理します。
